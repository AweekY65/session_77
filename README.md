# RTP：基于纯内存网络模拟器的可靠传输协议

在不可靠链路上提供有序、无重复、无缺失的字节流传输。**完全本地运行**：
不创建任何真实 socket，不连接互联网、消息服务或任何外部系统。网络行为由
`rtp/network.py` 中的虚拟时钟 + 事件队列模拟，所有随机性由种子控制，测试
完全确定、可复现。

## 目录结构

- `rtp/packet.py` — packet 编解码与 CRC32 完整性校验
- `rtp/network.py` — 纯内存网络模拟器（loss / duplicate / delay / reorder / corrupt）
- `rtp/protocol.py` — 滑动窗口发送端、接收端、连接驱动循环
- `tests/test_reliable_transport.py` — 端到端自动化测试

## Packet 格式

固定 15 字节头部（网络字节序）+ 负载：

| 字段   | 类型   | 说明 |
|--------|--------|------|
| seq    | uint32 | 数据包序号（按包计数） |
| ack    | uint32 | 累积确认号 = 下一个期望收到的序号 |
| flags  | uint8  | `DATA=0x01`，`ACK=0x02`，`FIN=0x04`（最后一个数据包置位） |
| length | uint16 | 负载字节数（上限 4096） |
| crc32  | uint32 | 对「crc 字段置 0 的头部 + 负载」计算的 CRC32 |

接收方解码时先校验长度与 CRC32，任何损坏的包直接丢弃，交由超时重传恢复。

## 滑动窗口算法

- 发送端把字节流按 `chunk_size` 切分为有限大小的 DATA 包，按包编号。
- 窗口参数 `window` 允许最多 N 个未确认包同时在途；
  `send_base`（最小未确认序号）到 `next_seq` 之间为可发送区间。
- ACK 采用**累积确认**：收到 `ack = k` 表示序号 `< k` 的包全部收到，
  窗口右滑。ACK 丢失时，后续更大的累积 ACK 可以一并确认，天然容错。
- 接收端维护期望序号 `expected` 与乱序缓存：
  - 序号 `< expected` 或已在缓存中的包为**重复包**，丢弃并重发 ACK；
  - 乱序到达的包进入缓存，**缺口补齐前绝不向上层交付后续连续数据**；
  - 只有从 `expected` 开始的连续片段才追加到交付缓冲，保证最终字节流
    不重复、不缺失、严格有序。

## 重传规则与错误状态

- 每个在途包独立计时，超过 `timeout`（虚拟时间单位）未确认即重传。
- 单个包重传次数达到 `max_retries` 后，连接进入 **error 状态**，
  `run()` 抛出 `ConnectionError_` —— 永久丢包时**绝不无限等待**。
- 接收端每收到一个 DATA 包都回复累积 ACK，重复包也会触发 ACK 重发，
  帮助发送端在 ACK 丢失后快速滑动窗口。

## 网络模拟器

`SimulatedNetwork` 按方向（data / ack）独立配置：

| 参数 | 含义 |
|------|------|
| `loss_rate` | 丢包概率 |
| `dup_rate` | 重复包概率（额外投递一份延迟副本） |
| `corrupt_rate` | 比特损坏概率（触发 CRC 校验失败） |
| `min_delay` / `max_delay` | 基础单向延迟 |
| `reorder_rate` / `reorder_extra` | 乱序概率与追加的额外延迟 |

不使用真实不稳定网络；虚拟时钟按事件堆推进，传输速度与真实时间无关。

覆盖场景（均校验最终内容的 SHA-256 哈希）：

- 无丢包基准传输
- 双向随机丢包（20%）
- 严重乱序（80% 乱序率 + 大额外延迟）
- 重复 packet（验证去重计数确实生效）
- ACK 丢失（40%）
- 比特损坏由 CRC 检测并恢复
- 永久丢包超过重试上限后报错退出（验证等待时间有界）
- 连接中途永久中断后报错
- 丢包 + 重复 + 乱序 + 损坏混合恶劣网络
- 空负载 / 1 字节 / 小负载边界
