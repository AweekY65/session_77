# rudp — 纯本地可靠传输协议（内存网络模拟器）

基于**纯内存网络模拟器**实现的可靠字节流传输协议。所有 packet、连接状态、
重传队列与测试数据只存在于本地进程内：不创建真实 socket、不连接互联网、
不依赖任何消息服务或外部系统。仅使用 Python 标准库（3.8+）。

## 目录结构

- `rudp/packet.py` — packet 编解码与 CRC-32 完整性校验
- `rudp/simnet.py` — 确定性内存网络模拟器（虚拟时钟 + 事件堆）
- `rudp/protocol.py` — sliding window 可靠连接
- `tests/test_rudp.py` — 自动化测试

## Packet 格式

大端序，定长 11 字节头部 + 变长 payload：

```
+----------------+----------------+---------------+------------------+
| seq  (4 bytes) | flags (1 byte) | len (2 bytes) | crc32 (4 bytes)  |
+----------------+----------------+---------------+------------------+
| payload (len bytes, 最大 65535) ...                                |
+-------------------------------------------------------------------+
```

- `seq`：packet 级序列号（0, 1, 2, ...），DATA 与 ACK 共用同一编号空间
- `flags`：`0x01 = DATA`，`0x02 = ACK`
- `crc32`：覆盖 `seq + flags + len + payload`，校验失败的 packet 直接丢弃
  （等效于丢包，由发送端超时重传恢复）

## 窗口算法（Sliding Window）

- 发送端把字节流切分为 MSS 大小的 DATA packet，每个分配递增序列号。
- 最多允许 `window_size` 个未确认 packet 同时在途；每收到一个 ACK 就从
  重传队列移除对应 packet，并把窗口向前滑动、继续发送后续数据。
- 接收端按序交付：只向上层交付从 `expect_seq` 开始的连续前缀；
  乱序到达的 packet 先缓存在接收缓冲区，缺失片段补齐前绝不交付后续数据，
  因此上层字节流不重复、不缺失、不乱序。
- 重复 packet 通过序列号去重（已交付或已缓存的直接忽略），但仍会重新
  发送 ACK——因为之前的 ACK 可能已丢失。

## 重传规则与错误状态

- 每个未确认 packet 独立计时，超过 `rto`（虚拟时间单位）未收到 ACK 即重传。
- 每个 packet 最多重传 `max_retries` 次；超过后连接进入 `ERROR` 状态并
  记录错误信息，**不会无限等待**（永久丢包场景下有界终止）。
- ACK 丢失通过对端的数据重传 + 重复 ACK 恢复，无需额外机制。
- 注意：`rto` 应大于链路最坏 RTT，否则会对正常在途 packet 误判超时。

## 网络模拟器

`SimNet` 用虚拟时钟和事件堆模拟有向链路，每条链路可独立配置：

- `loss`：丢包概率
- `duplicate`：重复包概率
- `corrupt`：比特翻转概率（由 CRC-32 检出）
- `delay` / `jitter`：基础时延 + 随机抖动（抖动自然产生乱序）
- `reorder` / `reorder_delay`：显式乱序（packet 被额外扣留）

随机源由固定 seed 驱动，测试完全可复现，不使用真实不稳定网络。

## 运行测试

```bash
cd <本目录>
python3 -m unittest discover -s tests -v
```

覆盖场景：无丢包、随机丢包（双向）、严重乱序、大量重复 packet、ACK 丢失、
比特损坏恢复、组合恶劣链路、窗口在途验证、双向传输，以及超过重试上限进入
`ERROR` 状态而非挂死。所有传输场景均校验最终内容的 SHA-256 哈希一致，
并验证接收端交付序列严格有序、无缺口。
